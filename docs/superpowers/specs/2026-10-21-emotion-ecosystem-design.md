# FaceMood Live Emotion Ecosystem v2 设计

## 目标与开发位置

按 2026-10-21 需求及后续修正，在 `codex/emotion-ecosystem-v2` 分支直接升级现有页面，不新增 Demo 路由、页面或应用入口。第一阶段交付 neutral / happiness / anger 三形态原型；性能与交互验收后才扩展八类并合并。形态是可见表情的美术隐喻，不推断内在心理状态。

现有基点为 `aacb705`。保留未跟踪的交接资料。开发期间不部署、不修改服务器或密钥、不使用 V100。

## 页面与数据流

现有 App.vue 保有摄像头、素材播放、人脸框、推理调度、模型加载、统计和导出。页面新增一个可关闭的生态系统视觉区域，摄像头与数据卡片使用高对比玻璃样式。窄屏按视觉区、摄像头、数据顺序排布，交互区外仍可正常滚动。

通过异步组件加载 Three.js 子系统；3D 模块导入、初始化和运行错误由局部边界处理并回退渐变背景，不传播到推理组件。视觉开关不卸载摄像头，不初始化或终止 InferenceEngine。

将已有 raw 概率、faces 和有效结果时间作为只读输入，避免对已平滑的 UI 概率重复 EMA。标签契约以 active.json 为准，按 label 而非需求表行号映射。现有统计和导出含义保持一致，3D FPS 独立显示。

页面提供明确标为“视觉预览”的三形态手动选择和自动轮播，独立于摄像头/素材模式；不把合成概率写入真实统计。退出预览恢复真实输入。阶段一其他五类暂显示 neutral idle，并明确标识原型尚未实现，不冒充已完成八形态。

## 组件边界

- EmotionScene：唯一 WebGL2 renderer、相机、灯光、可选后期、帧循环、交互平面 Raycaster、尺寸变化及生命周期。隐藏页面暂停渲染，恢复时限制 dt。
- EmotionRegistry：八标签配置、调色板、实现状态、程序化工厂或可选 GLB URL、许可信息与质量预算。本阶段仅三个程序化工厂，其他明确标为待实现；不下载第三方模型。
- EmotionEntity：持有独立 Object3D 与几何/材质，提供 update(dt, state)、onPointerForce(force)、setTransition(progress)、dispose()。共享资源的所有权需明确，退出后释放。
- FlowField：有界低分辨率速度/位移网格，指针速度产生高斯 splat，邻域传播、阻尼与回归力更新，输出纹理供网格顶点及粒子 shader 共同采样。不得仅使整体模型跟随指针冒充流体。
- EmotionController：纯 TypeScript 状态机，可注入时间和概率，不依赖 Vue、Three.js 或 Worker。
- GlassPanel / ThemeTokens：统一卡片、背景、按钮、图表和灯光色，随活跃形态缓慢过渡，并保持文字对比度。

## 三种实体与切换

neutral：多层半透明球壳与能量核心，呼吸、微旋，表面柔和波纹。
happiness：多层独立弯曲花瓣形成花朵，开合与上升孢子粒子，扰动推动花瓣展开。
anger：不规则有棱角晶体及碎块，缓慢收紧与受控裂隙发光，扰动使碎片暂时分散再聚合。

三者必须在灰度/同色截图中仍可凭轮廓区分。透明度、缩放与粒子消散交叉溶解默认 1000 ms；最多保留入场、退场两实体，快速切换请求合并，释放失效实体。不同拓扑不承诺顶点 morph。程序化资源按需创建；后续 GLB 仅预加载当前及最高候选，加载失败保留可见形态或 neutral。

## 控制器策略

初值：EMA alpha 0.25；进入候选置信度至少 0.55，且领先当前类别至少 0.12；候选连续成立 250 ms，当前主体保持至少 900 ms 后切换。所有参数集中可调。

无脸、输入为空、非有限/错误长度概率、模型加载失败时取消候选并进入 neutral idle。低置信持续 700 ms 进入 neutral idle，避免单次噪声切换。持续运行的摄像头/视频若 2000 ms 没有有效结果则 idle；图片识别成功可保持结果，停止、切换来源和清除预测时重置。后台恢复不追补过期动画。

## 指针与运动

Pointer Events 覆盖鼠标和触屏：坐标归一化，经 Raycaster 投影到场景交互平面，根据有上限的速度注入流场。触屏拖动采用 pointer capture，并处理 up、cancel、lost capture 与多点输入。离开或松手后清除施力状态，由阻尼和回归力缓慢恢复，不累计永久平移。

外围粒子使用 BufferGeometry + ShaderMaterial，在 GPU 采样同一场纹理，并叠加低频噪声漂浮。减少动态效果模式关闭自动轮播、强脉冲和持续漂移，保留低幅直接交互及静态 3D。

## 质量与容错

预算初值：low 1000 粒子 / DPR 1 / 64 场网格 / 无 bloom；medium 3000 / DPR 1.25 / 64 / 无 bloom；high 8000 / DPR 1.5 / 128 / 可选 bloom。首阶段由用户手动在 low / medium / high 预设间切换，避免因短时帧抖动频繁重建；依据持续帧耗时的观察窗口和冷却机制进行自动降档，作为后续增强，不计入首阶段验收。界面展示实际档位。

检测无 WebGL2 或 context lost 时停止帧循环并降级，识别仍可使用。context restored 后最多保留一个 renderer/循环并尝试重建；重建失败提供明确静态降级。resize、卸载和画质改变释放 listener、RAF、纹理、几何、材质、后期 target 与 renderer。

## 验证与交付证据

控制器测试覆盖候选、保持时间、低信度、无脸、标签映射和输入重置；流场测试覆盖传播、衰减、有界性与恢复。浏览器验证三种轮廓、交叉溶解、鼠标/触屏扰动、质量切换、减少动态效果、页面隐藏及 WebGL 失败隔离，并运行现有回归测试与构建。

性能报告区分现有基点与新分支，在同设备、浏览器、素材、模型 SHA 下记录冷/热首屏、35 MB 模型下载、分类吞吐、端到端延迟、3D FPS、资源大小、内存趋势及 CPU/GPU 工具观察。程序化 MVP 无外部 GLB 下载，仍需核对 Three.js chunk 与模型的加载竞争。

桌面 50–60 FPS、手机 24–30 FPS 仅为目标。Playwright viewport 或 WebKit 自动化不得替代 iPhone Safari 真机。若没有设备，记录“未测试”，列出测试步骤和未关闭的验收项，不进入八形态扩展或主分支合并。

新增 assets/ATTRIBUTION.md 记录自制几何、Three.js 版本和许可证来源；使用第三方资产前核验逐项许可并保留源文件及署名。本阶段不声称已集成任何外部艺术模型。

## 回滚

运行时视觉开关立即关闭 3D 并保留识别。发布回滚须恢复独立保存的旧前端构建/版本，不使用仅重置模型的 rollback:baseline 冒充视觉回滚。记录原 commit、构建校验与恢复步骤；不强制重置 active.json，不清除模型缓存，不自动变更线上服务。

## 阶段门槛

本设计审阅后编写实施计划；首阶段直接改现有页面并保持在开发分支。三形态交互、回归及目标真机验收完成后，再确认扩展 surprise / sadness / fear / disgust / contempt，最终才合并和发布。
